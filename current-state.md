## Test classification

Tests are classified into three categories to distinguish build success from semantic compatibility:

- **build_smoke**: Tests that compilation succeeds (syntax parsing, name resolution, lowering to WASM). These do NOT verify runtime semantics.
- **semantic_diff**: Tests that Node.js and iwasm execution produce identical output (differential testing).
- **parser_smoke**: Tests that syntax can be parsed (not yet implemented).

**Build pass does NOT imply semantic compatibility.**

Test files follow naming conventions:
- `*_build_smoke()`: Build smoke tests (m7_control_flow.rs, m8_oop_classes.rs, m9_modules.rs, m10_node_apis.rs)
- `*_semantic_diff()`: Differential tests (m2_node_diff.rs)
- `m2_node_diff.rs`: Semantic differential tests for core fixtures

Compile-only tests for class/module/Node API are explicitly marked as build_smoke to avoid implying semantic support.

## TypeScript parse / erase / emit boundary

`docs/05-compatibility-and-semantics.md` defines the final-state TypeScript boundary for parse-and-erase, module/emit-shape preservation, TypeScript transform ownership, and TypeScript-specific unsupported diagnostics. Current implementation covers the initial ambient declaration boundary for representative declaration-only `declare class`, `declare function`, `declare const/let/var`, `declare enum`, and class-element `declare` forms, erasing them before runtime lowering. Ambient variable or class-element initializers remain rejected to avoid silently introducing runtime values; ambient `declare module` / `declare namespace` forms route to `UnsupportedModule`, and unsupported ambient/runtime TypeScript enum forms produce source-spanned `UnsupportedTypeScriptSyntax`. Remaining concrete follow-up ownership is tracked by issue 345 (`type-alias` erasure), issue 346 (`declaration-emit`), and narrower future ambient/module slices if expanded coverage requires them.
