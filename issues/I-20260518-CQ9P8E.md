## Notes

### Root cause
The WAT function `$array_concat` (accessor.rs:63-108) has signature:
```
(func $array_concat (param $a i32) (param $b i32) (result i32)
```
It takes exactly 2 array params. But `Array.prototype.concat()` accepts variadic arguments:
```js
[1, 2].concat([3], [4, 5], 6)  // N args
```

The IR layer at `program_builtins.rs:345` routes concat to `RuntimeFn::ArrayConcat`, then emits a `RuntimeCall` with N arguments directly to the WAT function — but the WAT function only accepts 2 params, causing a runtime crash when >2 args are passed.

### Fix approach
Special-case in the IR emit layer (expr_emit.rs or similar) like `String::Concat` — reduce variadic concat to binary chain, or expand WAT to handle N args via iterative merging.

### Comparison
This is the same class of bug as `String::Concat` (previously fixed): a WAT function with fixed arity receiving variadic IR args.
