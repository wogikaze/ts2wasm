## Problem

Parser/frontend work must be assignable separately from IR/runtime work, and declaration-only success must not inflate executable coverage. Current `tsc/tsgo` coverage does not expose parser/erasure/executable boundaries, and `--explain-unsupported` only partially maps diagnostics to TS phases.

## Steps

1. Add `ts_boundary` schema field: `ts-parse | ts-erase | ts-declaration-only | ts-emit | ts-runtime | unknown`
2. Add schema fields `executable_source`, `declaration_only`, `declaration_only_reason`
3. Add summary counters `ts_boundary_counts`, `parse_accept`, `erase_only`, `declaration_only`, `executable_build_pass`
4. Print `ts_boundary` in `--explain-unsupported` when available

## Acceptance

- [ ] Schema includes `ts_boundary` (ts-parse, ts-erase, ts-declaration-only, ts-emit, ts-runtime, unknown)
- [ ] Schema includes `executable_source` and `declaration_only` boolean fields
- [ ] Summary counters for TS boundaries (`ts_boundary_counts`, `parse_accept`, `erase_only`, `declaration_only`, `executable_build_pass`)
- [ ] `--explain-unsupported` prints TS boundary
- [ ] Existing `tsc/tsgo` ramp commands keep working

```bash
cargo test -p ts2wasm-cli --test typescript_directives
mise run reference-coverage -- tsc --limit 30 --no-semantic
mise run reference-coverage -- tsgo --limit 20 --no-semantic
```

## Non-goals

- Do not implement new TypeScript syntax or full type checking
- Do not change existing `tsc/tsgo` coverage commands

## Risk

Diagnostics may be underspecified; store `ts_boundary=unknown` only with tracking and reason.
