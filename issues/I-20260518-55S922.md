## Notes

### Initial investigation (2026-05-19)

**Analysis of 57 test262 String failures:**
- 54 "output mismatch" failures: ALL Annex B non-standard methods (HTML wrappers, substr, trimLeft/trimRight) — property descriptor tests, not WAT fixes
- 3 crash/assertion failures: All use `$262.IsHTMLDDA` with `@@replace`/`@@split` protocol tests — our runtime doesn't implement this protocol
- All 695 node_diff tests pass (0 failures) — basic string functionality works

**Root cause of WASM crash (fixed):**
- `emit_regexp_match_from` in `runtime/regexp/emit.rs` is called from TWO places: `emit_string_split` and `emit_string_replace`
- Had NO duplicate-emission guard — if both StringSplit and StringReplace are needed in the same program, `$regexp_match_from` would be emitted twice
- This produces invalid WAT and causes "WASM module load failed: type mismatch" crashes
- Fixed by adding guard: `if wat.contains("$regexp_match_from") { return; }`
