## Notes

- Split from `I-20260513-P5PH9E`: straight-line generator body statements before each yield now execute lazily for statically visible generator iterator locals, but the implementation tracks `next()` index at compile time.
- Remaining semantic gaps:
  - two iterator objects from the same generator function need independent runtime state;
  - branch and loop control flow must execute through runtime resume labels;
  - statements after the final yield should run when the generator is resumed to completion;
  - direct `gen().next()` and aliasing should not depend on compile-time call ordering.

## Acceptance

- Add Node diff fixtures for branch/loop yields and trailing side effects after the final yield.
- Replace compile-time `next_index` tracking with runtime resume-state execution driven by generator state.
