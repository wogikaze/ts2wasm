## Notes

### Fix applied (2026-05-19)

**typeof fix**: Added Symbol sentinel check in `emit_typeof` WAT function. Previously, Symbol values (tag=7 object tag with SYMBOL_SENTINEL=-3 in heap header) fell through to the "object" branch. Now returns "symbol" string correctly.

Before the fix:
- `typeof Symbol.hasInstance` returned "object"
- This broke ~32 test262 tests that rely on `assert.sameValue(typeof Symbol.hasInstance, 'symbol')`
- Also broke `verifyProperty` (used in test262 harness) which internally calls `Object.getOwnPropertyDescriptor` and checks property descriptors against typeof results

**valueOf routing**: Added `("Symbol", "valueOf") => Some(RuntimeFn::ValueOf)` in `collection_method_runtime_fn` in `program_builtins.rs`. This allows Symbol.prototype.valueOf to route through class-based dispatch on typed Symbol locals. `("Symbol", "toString")` was already mapped.
