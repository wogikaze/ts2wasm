## Notes

### Implementation

**Workstream A: DuplicateFunction fix (24 cases)**

Three layers rejected duplicate function declarations unconditionally. All three now check the directive prologue for `"use strict"` before rejecting duplicates:

1. `crates/compiler/src/stages/parse.rs:validate_ast()` — AST-level validation
2. `crates/resolve/src/name_resolver.rs:resolve_program()` — Name resolution pass
3. `crates/ir/src/lowered/program.rs:collect_function_ids()` — IR lowering pass

All three use the same pattern: scan the directive prologue (initial string expression statements) for `"use strict"`. If absent, duplicate function declarations are allowed per ES spec (web compat, last definition wins).

**Workstream B: DuplicateParameter (24 cases)**

Already handled at the IR level (`crates/ir/src/lowered/resolver/mod.rs`) via `resolver.ctx.is_strict_context()` check. Existing tests `lowering_rejects_duplicate_parameter_in_strict_mode` and `lowering_accepts_duplicate_parameter_in_non_strict_mode` verify both paths.
