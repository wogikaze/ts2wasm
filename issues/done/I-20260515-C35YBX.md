## Acceptance
- Add object/prototype and closure/function-object GC boundary tests tied to runtime layout descriptors.
- Classify runtime/GC coverage failures by trap class instead of collapsing them into generic fail.
- Keep object semantics kernel invariants aligned with GC scanner expectations before expanding object/prototype coverage.
- **Object layout documentation**: Add object layout table in `docs/14-runtime-abi.md` with offsets for property count, flags, prototype pointer, entries, private slot area, and descriptor bit fields. Add backend structural tests that object runtime helpers use `Layout::OBJECT_*` constants, not hard-coded offsets.
- **Scanner/kernel parity**: For every object payload field that can contain `RawValue`, verify there is a corresponding mark path in `$gc_mark_object_payload` (prototype, key/value entries, private slots, closure captures, symbol descriptions, BigInt no-child). Add architecture rule or grep test rejecting raw object entry scans outside approved runtime kernel/GC files.
- **Closure GC ABI boundary**: Document closure object payload fields (sentinel `-2`, `code_id`, `capture_count`, reserved flags, capture slots). Ensure closure allocation uses `$alloc_heap_kind(..., GC_KIND_OBJECT, 0)`. Add GC scanner test that closure sentinel dispatch scans exactly `capture_count` capture slots and no ordinary object entries. Add returned-closure pressure fixture where closure captures an object containing an array, invoked after allocation pressure.
