## Fix: Remove (0, eval) from COMMON_HOST_PRELUDE to eliminate $host_eval_indirect import

**Problem**: The `COMMON_HOST_PRELUDE` in `scripts/lib/test262_harness.py` contained
`(0, eval)(source)` inside `test262_evalScript`, which triggered `$host_eval_indirect`
(indirect eval) import in the compiled WASM. Since the prelude is injected for ALL
tests that have includes/features/assert patterns, every test got this import.

The iwasm runner does not register `host.eval.indirect`, so WAMR printed:
```
warning: failed to link import function (host, eval.indirect)
```
This warning went to stdout, causing output mismatch with the Node reference.

**Fix** (2 files):

1. `scripts/lib/test262_harness.py`: Replaced `(0, eval)(source)` in
   `test262_evalScript` with a throwing stub:
   ```
   throw new Error("$262.evalScript is not supported by this runner slice");
   ```
   Updated `NODE_HOST_PRELUDE` to use the new stub string for replacement.

2. `crates/compiler/src/test262_preprocessor.rs`: Added
   `rewrite_assert_throws_to_try_catch()` function that rewrites
   `assert.throws(ErrorType, function() { BODY })` patterns to inline try/catch
   blocks, eliminating function expressions that could generate `$host_eval_indirect`.
