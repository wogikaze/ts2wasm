## Notes

### Fix implemented

The 3 test262 cases that produced `UnsupportedTypeScriptSyntax` all use valid ES decorator syntax:
- `@yield() class {}` — decorator call expression
- `@yield class {}` — decorator member expression
- `@(yield) class {}` — decorator parenthesized expression

**Root cause**: The parser (`expressions_main.rs`) rejected ALL `@` tokens in expression position as "TypeScript decorator syntax not supported."

**Fix**: Instead of erroring, the parser now consumes the decorator expression (identifiers, dots, balanced parens for calls/paren-exprs) and then parses the `class` expression normally. The decorator is a no-op (erased at the parser level).

### File changed
