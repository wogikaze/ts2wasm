## Problem

Runtime failures need assignment labels for object semantics, arrays, closures, completion records, memory/GC, and host import errors. Currently all runtime failures collapse into generic `fail` in coverage output, making it impossible to triage which runtime domain is responsible.

## Steps

1. Add `runtime_label` schema field: `object-kernel | array-exotic | closure-env | completion-record | builtin-method | runtime-memory | host-import`
2. Add `runtime_trap` schema field: `{kind, exit_code, signal, message}` with `kind = wasm_validation | iwasm_trap | runtime_oom | gc_invariant | timeout | host_import_missing | unknown_runtime_error`
3. Classify runtime failures from case path, diagnostic, metadata, runtime stderr, and iwasm exit code
4. Add runtime label/trap top-N buckets to triage reports

## Acceptance

- [ ] Schema includes `runtime_label` (object-kernel, array-exotic, closure-env, completion-record, builtin-method, runtime-memory, host-import)
- [ ] Schema includes `runtime_trap` with `kind` (wasm_validation, iwasm_trap, runtime_oom, gc_invariant, timeout, host_import_missing, unknown_runtime_error)
- [ ] Runtime stderr / iwasm exit / path / metadata classified to labels
- [ ] Runtime labels and trap kinds appear in triage reports
- [ ] Semantic mismatch remains distinct from runtime error
