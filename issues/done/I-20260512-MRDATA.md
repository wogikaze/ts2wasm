## Notes

### Goal

Turn MIR from a type alias boundary into an actual data model without forcing backend migration in the same slice.

### Acceptance

- `MirProgram`, `MirFunction`, `MirStmt`, and `MirExpr` are native types, not type aliases.
- Existing `LoweredProgram` path remains available through a compatibility conversion.
- `lower_hir_to_mir` can produce native MIR or an explicitly named compatibility bridge.
- Public names keep the `Validated<MirProgram>` boundary intact.
- Focused tests prove the conversion does not change existing supported HIR -> MIR snapshots.

### Non-goals

- No native MIR WAT emitter in this issue.
- No default compiler pipeline switch.

## Evidence

- native MIR data model verified with compatibility bridge tests and docs synchronized
