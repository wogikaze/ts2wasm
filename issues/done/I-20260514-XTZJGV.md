Title: Dispatch object literal methods after computed-key lowering
Summary: Computed-key object literals materialize method properties, but direct calls like obj.a() do not populate object_function_props and fail as Object.a.
Next:
---

## Notes

### 2026-05-14 discovery

- Reproduction fixture during computed-method parser work:
  - `fixtures/core-expressions/object-literal-computed-method.ts` with `console.log(obj.a())` or `console.log(obj.b())`
- Build diagnostic:
  - `error: [UnsupportedBuiltin/lowering] method \`Object.a\` not found`
- Root cause hypothesis: computed-key object literals lower through `lower_object_literal_expr_with_computed_keys`, producing a block expression rather than a plain `ObjectNew`. `function_props_for_lowered_object_expr` only extracts callable object properties from `ObjectNew`, so `object_function_props` is not populated for direct method dispatch.

### 2026-05-15 fix

- Extended lowered object function-property extraction to understand computed-key block expressions and apply object property writes in order.
- Preserves direct-call dispatch for static method keys and computed method keys that resolve to known string locals, while clearing/declining unknown dynamic keys instead of assuming they cannot overwrite a method.
- Added `fixtures/core-expressions/object-literal-computed-method-call.ts` covering:
  - static computed method direct call: `obj.a()`
  - non-function computed data property: `obj.b`
  - computed method from a known string local: `obj.c()`
- Validation:
  - `cargo test -p ts2wasm-cli build_smoke_object_literal_computed_method_call -- --exact` initially failed with `method \`Object.a\` not found`, then passed.
  - `cargo run -p ts2wasm-cli -- build fixtures/core-expressions/object-literal-computed-method-call.ts -o /tmp/ts2wasm-object-literal-computed-method-call.wasm`
  - `node fixtures/core-expressions/object-literal-computed-method-call.ts`
