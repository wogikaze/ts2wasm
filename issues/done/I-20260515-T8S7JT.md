## Problem

Host imports are both ABI and security boundary. The current runtime catalog structure is sufficient, but `validate_runtime_link_plan` is a placeholder and `CapabilityManifest::validate()` is not called before emission. Reason keys are inconsistent across imports.

## Steps

1. Implement `validate_runtime_link_plan` for import specs, WASI capability matches, Node shim capability matches, and reason presence
2. Normalize reason keys: `wasi.stdin`, `wasi.stdout`, `wasi.args`, `wasi.env`, `wasi.clock.realtime`, `wasi.random`, `wasi.filesystem.read/write`, `host.<domain>.<function>`
3. Call `CapabilityManifest::validate()` before manifest JSON is returned or written
4. Extend `manifest-imports.py` to compare full WASM import pairs with manifest imports

## Acceptance

- [ ] `validate_runtime_link_plan` checks implemented (import specs + capability reasons)
- [ ] Capability reason keys normalized (`wasi.stdin`, `host.<domain>.<function>`)
- [ ] `CapabilityManifest::validate()` called before manifest emission
- [ ] Inconsistent link plans fail validation
- [ ] Backend cannot emit invalid JSON manifest
- [ ] Manifest imports match WASM imports for core fixtures

## Non-goals

- Do not add new Node APIs or full filesystem permission modeling
- Do not change the WASM import structure

## Risk

Existing implicit imports may fail validation; fix by adding explicit reasons in the catalog, not by weakening validation.
