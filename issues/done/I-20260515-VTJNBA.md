## Problem

Coverage denominators are not meaningful if the local reference corpus can change silently. Currently `reference/` exists and `reference-coverage.py` knows suite paths, but there is no lockfile recording commit, hash, or file count for verification.

## Steps

1. Add lock entries schema: `suite`, `root_relative_path`, `remote_url`, `commit`, `content_hash`, `file_count`, `denominator`, `generated_at`
2. Create `reference/corpus-lock.json` with initial lock data
3. Implement `scripts/run/reference-corpus.py` with `verify | write-lock | print-evidence` commands
4. Wire `reference-coverage --check-prerequisites` to `verify` unless `TS2WASM_REFERENCE_LOCK_MODE=off`
5. Write `evidence.corpus = {lock_hash, suite_commit, file_count}` in coverage output

## Acceptance

- [ ] `reference/corpus-lock.json` exists with lock schema (suite, URL, commit, hash, file_count)
- [ ] `scripts/run/reference-corpus.py` implements `verify | write-lock | print-evidence` commands
- [ ] `reference-corpus` mise command registered
- [ ] `--check-prerequisites` flag works in `reference-coverage.py`
- [ ] Verification fails on file count / hash mismatch
- [ ] Coverage evidence contains corpus lock data

```bash
python -m py_compile scripts/run/reference-corpus.py scripts/run/reference-coverage.py scripts/manager.py
mise run reference-corpus -- verify
mise run reference-coverage -- test262 --check-prerequisites
```

## Non-goals

- Do not clone reference repos over the network during gates
- Do not require full-corpus lock for local ad hoc exploration

## Risk

Agents without corpora will fail the gate; provide clear errors and allow opt-out (`TS2WASM_REFERENCE_LOCK_MODE=off`) only for non-gate exploration.
