Title: Architecture wave: TypeScript erasure coverage boundary
Summary: Record TS erasure/rejection decisions in tsc/tsgo coverage without assigning runtime policy to frontend.
Next: Implement TS erasure reports, parser smoke class, and oracle isolation checks.

---

## Acceptance
- Emit TypeScript erasure/rejection decision records for tsc/tsgo coverage runs.
- Treat parser smoke as a first-class non-semantic fixture class and keep TypeScript oracle isolation explicit.
- **Parser smoke test class**: Add `crates/cli/tests/parser_smoke.rs` that runs pass/fail fixtures through the parser only (no build/runtime). Add `TypeScriptBoundaryRecord` test helper JSON schema: `{"source","construct","category","runtime_nodes_emitted","diagnostic"}`. Categories: `parse-and-erase`, `parse-and-preserve`, `parse-and-lower`, `reject-as-unsupported`.
- **Fixture additions**: Add fixtures for `type alias`, `interface`, `type annotation`, `as`, `satisfies`, `generic type parameters`, `declare class/function/const`, and rejected ambient initializer. Assert erased constructs produce `runtime_nodes_emitted == 0`. Assert rejected forms use exact `DiagCode`: `UnsupportedTypeScriptSyntax`, `UnsupportedModule`, or `UnsupportedRuntimeSubset`.
- Attribute frontend coverage reasons to parser syntax, TypeScript erasure, unsupported builtin, harness, reference, or unknown categories.
- **Frontend-attributed feature labels (REQ-COV-004)**:
  - Define coverage feature labels: `parser-syntax`, `typescript-erasure`, `frontend-invalid-source`, `frontend-unsupported`, `name-resolution`, `runtime-subset`.
  - Diagnostics emitted by lexer/parser/AST validator/type-reference directive/type-erasure validation carry enough `phase` or message token for `reference-coverage.py` to map into the labels.
  - Update unsupported classifier to map `DiagCode::SyntaxError` with phase `parser` to `parser-syntax`, TypeScript erasure diagnostics to `typescript-erasure`, and explicit invalid test source to `frontend-invalid-source`.
  - Add feature label counts to triage JSON from REQ-COV-002.
  - Add a parser syntax invalid fixture and expected feature label; add a TypeScript erasure unsupported fixture and expected `typescript-erasure`; add JSONL schema test that `feature` is required for `outcome=unsupported`.
- **ErasureReport API (REQ-FE-003)**:
  - Add public frontend module `typescript_erasure` with `ErasureReport { erased: Vec<ErasedSyntax>, unsupported: Vec<UnsupportedTsSyntax> }`, `ErasedSyntax { kind: ErasureKind, span: Span }`, `ErasureKind` enum (TypeAnnotation, InterfaceDecl, TypeAliasDecl, AmbientDecl, AmbientNamespace, GenericParams, AsAssertion, Satisfies, ConstAssertion, TypeOnlyImport), and `UnsupportedTsSyntax { feature, span, diagnostic_code, tracking }`.
  - Implement `collect_erasure_report(program: &[Stmt]) -> ErasureReport`.
  - Runtime-bearing TS syntax that is not supported emits `DiagCode::UnsupportedTypeScriptSyntax` with feature: `enum`, `namespace-runtime`, `declaration-emit`, `module-augmentation`, `type-only-import-runtime`.
  - Add CLI dump option `ts2wasm dump --ast --erasure-report <file>` or extend `dump --ast` JSON/text output with `--erasure-report` to print stable JSON.
  - Frontend unit tests for `collect_erasure_report` on type annotation, interface, type alias, ambient declaration, satisfies/as/const/generic fixtures.
  - Add CLI test `typescript_erasure_report.rs` checking stable JSON keys.
