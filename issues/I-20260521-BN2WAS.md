Title: Epic: Bun に勝つ ts2wasm raw execution lane
Summary: Bun に勝つため、JS互換 slow path と raw Wasm fast path を両立する勝利条件と全体計画を固定する。
Next: Create benchmark baselines, then implement raw value lanes, guard/bailout, typed data paths, and final Bun victory gates.

---
## Non-goals
- Beating Bun on arbitrary npm/Node applications, dynamic prototypes, generic JS object-heavy workloads, or RegExp-heavy text processing.
- Faster cold startup than Bun for general TypeScript projects.
- Semantic compatibility without guard fallback.
- SIMD or multi-threaded Wasm as a substitute for single-threaded scalar optimization.
- Any form of JIT compilation or runtime code generation.

## Acceptance
- [ ] This epic has exactly one dependency graph covering the included Bun-victory issues.
- [ ] The project defines three separate performance views: execute-only, compile-only, and build-run.
- [ ] Tier-1 execute-only victory: ts2wasm+wasmtime-aot geomean <= 0.80 * bun run.
- [ ] Tier-2 warm build-run victory: geomean <= 0.90 * bun run with cache/server.
- [ ] Cold build-run tracked separately, not hidden inside execute-only.
- [ ] Hot WAT bodies contain no generic helper calls from the denylist.
- [ ] Compatibility preserved by guard + slow path, not by trusting TS annotations.

## Notes
The current compiler is still close to a tagged-value runtime in Wasm. This epic changes direction from "make helpers faster" to "remove helpers from hot paths".
