## Notes

- Discovered while closing `I-20260514-67ZV8S` symbol-key accessor parity.
- Repro shape:
  - `const a = Symbol("slot"); const b = Symbol("slot");`
  - Define object properties/accessors with `[a]` and `[b]`.
  - Node treats `a` and `b` as distinct keys; current dynamic object runtime paths stringify symbol values and can collapse both to `Symbol(slot)`.
- `I-20260514-67ZV8S` now has a static accessor-dispatch workaround for statically visible symbol locals, but that does not fix general runtime symbol-key storage, descriptor lookup, enumeration, or dynamic aliasing.
- 2026-05-15: The symbol object-method slice now gets `language/computed-property-names/object/method/symbol.js` past `object.a()`, `object[sym1]()`, `object.c()`, and `object[sym2]()`; the next blocker is the final `Object.getOwnPropertySymbols(object)` assertion, which needs symbol-key enumeration backed by identity-preserving object storage.
- 2026-05-15: Dynamic `obj[symbol]` get/set now preserves symbol identity for ordinary property assignment by storing symbol keys with an internal runtime sentinel path. `Object.defineProperty`, descriptor lookup, deletion, `in`, and symbol enumeration still need the same identity-preserving key path before this issue can be closed.
