## Notes

### Root cause
The WAT function `$array_for_each` at `iteration.rs:720-757` has the correct signature:
```
(func $array_for_each (param $arr i32) (param $callback i32) (result i32)
```
It accepts both the array AND a callback parameter. **However**, the loop body (lines 744-745) only increments `$i` and branches back — it **never calls the callback**:
```wat
(local.set $elem (i32.load ...))
(local.set $i (i32.add (local.get $i) (i32.const {one})))
(br $scan)
```
The callback parameter is accepted but entirely unused. The function always returns `undefined` without any side effects.

### Fix approach
Add a callback invocation in the loop body that calls `$callback` with (elem, index, array) arguments. The callback invocation pattern can be modeled after `emit_array_map` (iteration.rs:759+) which does call the callback.

### Note
This is different from the filter/every/find family: `ArrayForEach` is NOT in `is_identity_array_method()` and DOES accept the callback param. The bug is purely in the WAT implementation — the callback is simply not called.
