## Notes

### Goal

Strengthen typed WasmIR as a shared backend input for both text and binary output.

### Acceptance

- Add small `WasmModule` fixtures covering imports, memory, globals, data, functions, and exports.
- Emit the same fixtures through `WatWriter::emit_module` and the feature-gated `wasm-encoder` backend.
- Validate WAT and binary outputs when local validation tools are available.
- Record unavailable-tool caveats rather than treating missing tools as pass.

### Non-goals

- No full binary backend migration.
- No runtime ABI layout changes.

## Evidence
- cargo test -p ts2wasm-backend-wasm --test wasm_encoder_parity --features wasm-encoder-backend => 10/10 passed

- `cargo test -p ts2wasm-backend-wasm --test wasm_encoder_parity` => 5/5 passed (WAT path)
- `cargo test -p ts2wasm-backend-wasm --test wasm_encoder_parity --features wasm-encoder-backend` => 10/10 passed (WAT + binary paths)

## Bugs found and fixed
1. **wat_writer module private**: Integration test couldn't access `WatWriter`. Fixed by changing `mod wat_writer` → `pub mod wat_writer` in `lib.rs`.
2. **Import `$` prefix missing**: `(func print_i32)` should be `(func $print_i32)`. Fixed in `emit_module()`: `(func {}` → `(func ${}`.
3. **Missing `End` opcode in binary backend**: `build_single_function()` in `wasm_encoder_backend.rs` didn't emit `End` after the instruction loop. Binary wasm requires explicit `End` opcode for each function body.
