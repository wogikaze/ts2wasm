## Notes

### Motivation

Full semantic-fast coverage of 53K test262 files (~24K iwasm executions) cannot fit in 300s regardless of wasm runtime:
- iwasm lower bound: ~500s (24K × 0.5s / 24 workers)
- wasm emit: ~114s

A sampled semantic mode provides confidence in correctness without full execution.

### Modes

| Flag | Behavior | Target |
|------|----------|--------|
| `--no-semantic` | build-only (~60s) | default daily |
| `--semantic fast --sample N` | deterministic iwasm sample of N files | daily/local |
| `--semantic fast` (no sample) | full iwasm semantic | CI/nightly |
| `--semantic strict` | Node oracle full differential | nightly/manual |

### Sampling requirements

- Deterministic by file-path hash and `--sample-seed` (or `TS2WASM_SAMPLE_SEED`).
- Stable across runs unless seed changes.
- Stratified categories:
  - test262 feature flags
  - negative/positive tests
  - build status (pass/fail baseline)
  - previously semantic_pass / semantic_fail
  - changed files (diff-aware, stretch goal)
- Always include semantic regression canaries.
- IR change + sample run should detect regressions with high probability.

### 2026-05-16: Deterministic sample selection

Added deterministic seed-based sampling for test262.

**Changes in `scripts/run/reference-coverage.py`:**
1. Added `--sample-seed SEED` CLI argument (falls back to `TS2WASM_SAMPLE_SEED` env var, then empty).
2. Sort files by path before sampling for deterministic base order.
3. Per-category file selection: group files by category, sort by `sha256(file_path + seed)` when seed is set, take first `sample` per category.
4. Without seed: sorted alphabetical base order (deterministic).

**Verification:**
- Same seed (abc): `7d67d970...` → same SHA256 across runs ✅
- Different seed (xyz): `51c0bb04...` → different SHA256 ✅  
- No seed: `b1b4279a...` → deterministic (same across runs) ✅
- `--sample-seed` CLI flag works alongside `--sample` ✅

### 2026-05-16: semantic_skipped_sample JSONL records + summary counts

Added `semantic_skipped_sample` records for non-sampled files in JSONL mode.

**Changes in `scripts/run/reference-coverage.py`:**
1. Added `semantic_skipped_sample` counter initialization.
2. Added `non_sampled_files` computation: after selecting sampled files, compute the set difference of all files minus sampled files.
3. Added lightweight JSONL record emission for non-sampled files: after the main JSONL write, open the file in append mode and write a `semantic_skipped_sample` record per non-sampled file. No actual compilation is done — records are written directly.
4. Updated `build_test262_jsonl_summary()` to accept and include `semantic_skipped_sample` in the summary dict.
5. Updated summary output to include `selection.sample_selected` and `selection.total_available`.
6. Updated print line to show `SemSkipSample` count.
7. Updated `total` progress counter to include non-sampled files.

**Verification:**

- Summary JSON contains `semantic_skipped_sample: 53457` and `selection.sample_selected: 12`, `selection.total_available: 53469` ✅

### 2026-05-16: Performance fix — WAMR runner timeout + release binary

Achieved **2m35s** for `mise run reference-coverage -- test262 --semantic fast --sample 2000` (under 300s target).

**Root causes of previous performance issues:**

1. **Debug binary used for server**: `resolve_ts2wasm_binary()` picked the newest binary by mtime. Since `cargo build` (debug) is run frequently, the debug build was always newer than release, causing the ts2wasm server to run ~7× slower. Fixed in `scripts/lib/ts2wasm_binary.py` to prefer release over debug regardless of mtime.

2. **WAMR runner hangs on long-running wasm**: The C runner's SIGALRM handler (`alarm_handler`) returns without interrupting CPU-bound `wasm_application_execute_main()`, so wasm files with long execution times hang the runner permanently. Fix: added a daemon-thread timeout (10s) to `readline()` in `run_wasm_oracle_for_item()`; on timeout, kill the runner and fall back to `subprocess.run(["timeout", "5s", "iwasm", ...])`.

**Perf test results:**
```
mise run reference-coverage -- test262 --semantic fast --sample 2000
real    2m35.382s   ← under 300s ✅
user    3m0.636s
sys     0m58.051s
```
