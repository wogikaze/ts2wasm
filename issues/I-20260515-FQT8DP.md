## Problem

Coverage and manifests need to identify the runtime ABI and canonical target that produced a WASM module. Currently `crates/runtime-abi` has constants/layout contracts and compat snapshots, but generated manifest JSON and WASM do not expose ABI version or canonical target ID. Target strings are inconsistent (`wasm32-wasi`, `wasm32-wasi-p1`, `wasm32-wasi+node-host`, `wasm32-wasi-p1+node-shim`).

## Steps

1. Add `RUNTIME_ABI_NAME = "ts2wasm-runtime-abi"` and `RUNTIME_ABI_VERSION: u32` constants in `crates/runtime-abi`
2. Emit manifest fields `runtime_abi_name`, `runtime_abi_version`, `target_id`, `target_aliases`
3. Emit WASM custom section `ts2wasm.abi` with canonical JSON matching manifest metadata
4. Define canonical target IDs `wasm32-wasi-p1` and `wasm32-wasi-p1+node-shim`; preserve legacy target strings as aliases
5. Add tests comparing manifest and WASM metadata

## Acceptance

- [ ] `RUNTIME_ABI_NAME` / `RUNTIME_ABI_VERSION` constants defined
- [ ] Manifest includes `runtime_abi_name`, `runtime_abi_version`, `target_id`, `target_aliases`
- [ ] WASM custom section `ts2wasm.abi` emitted matching manifest metadata
- [ ] Canonical target IDs `wasm32-wasi-p1` and `wasm32-wasi-p1+node-shim` defined
- [ ] Legacy aliases accepted
- [ ] Existing manifest compatibility preserved through additive fields

## Non-goals

- Do not add WASI preview2, Component Model, or new memory layout
- Do not change existing manifest JSON structure

## Risk
