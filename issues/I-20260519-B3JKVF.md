## Resolution

Root cause: the `COMMON_HOST_PRELUDE` in `scripts/lib/test262_harness.py` contained `(0, eval)(source)` inside `test262_evalScript`, which triggered `host.eval.indirect` import in ALL compiled WASM. The iwasm runner doesn't register `host.eval.indirect`, so WAMR printed a warning to stdout on every test, causing output mismatch with the Node reference.

Fix (cherry-picked from commit `bac8b9a38`):
- Replace `(0, eval)(source)` in `COMMON_HOST_PRELUDE` with a throwing stub
- Update `NODE_HOST_PRELUDE` to use the stub string for replacement
- Add `rewrite_assert_throws_to_try_catch()` in `test262_preprocessor.rs` as defense in depth

Results on test262 Set/Map/WeakMap/WeakSet:
- Before: Pass=103, Fail=295, Unsupported=433, Blocked=4
- After:  Pass=398, Fail=0, Unsupported=433, Blocked=4
- Improvement: 295 new passes (all semantic_mismatch eliminated)

All 295 semantic_mismatch failures were caused by the eval.indirect warning. The remaining 433 unsupported are pre-existing compile-time limitations (new Map/Set with iterable, forEach with dynamic callbacks, missing methods like getOrInsert/getOrInsertComputed).
