### 2026-05-16 var hoisting fix

Root cause: the lowered resolver (`crates/ir/src/lowered/resolver/function.rs`) has its own scope chain and processes statements sequentially. When `console.log(callCount)` appears before `var callCount = 0`, the lowered resolver's `resolve_local("callCount")` fails because the name hasn't been registered in the lowered resolver's scope yet.

The name resolver (`name_resolver.rs`) handles this correctly via a first-pass pre-declaration of var names (lines 303-310). But `is_var` is discarded in `builtin_resolver.rs:1051` when creating `ResolvedStmt::Let`, so the lowered resolver can't distinguish var from let/const.

Fix: Added first-pass pre-declaration loops in two locations in `crates/ir/src/lowered/program.rs`:
1. In `lower_program_with_module_url` (top-level, around line 387): pre-declare all `ResolvedStmt::Let` names before the main lowering loop
2. In `lower_function` (function bodies, around line 4246): pre-declare all `ResolvedStmt::Let` names before `resolver.lower_block(body)`

Commit: `e823cf6d2`
