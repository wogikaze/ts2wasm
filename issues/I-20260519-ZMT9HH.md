## Root Cause
The WAT runtime code in `crates/backend-wasm/src/runtime/regexp/emit.rs` had two bugs:
1. All escape sequences other than \d and \w were incorrectly dispatched to kind=4 (whitespace), causing negated character classes (\D, \W, \S), literal escapes (\n, \t, \r, \f, \v), and word boundaries (\b, \B) to produce wrong results or crash at runtime.
2. The closing paren count for the kind==7 (\S) branch was one too many, which would produce invalid WAT when the \S escape was used.

## Fix
- Applied commit `00af943dd` and `64e416f3e` from master to the worktree:
  - Added kinds 5 (not-digit), 6 (not-word), 7 (not-space) to `$regexp_match_inner`
  - Rewrote escape dispatch in all 4 match functions ($regexp_test, $regexp_match, $regexp_match_from, $regexp_search) to correctly dispatch \D, \W, \S, \n, \t, \r, \f, \v, \b, \B
  - Added kind==10 handler for zero-width assertion pass-through
  - Fixed paren counts for kind==7 and fallthrough whitespace branches
