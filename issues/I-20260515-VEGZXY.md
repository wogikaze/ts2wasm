## Problem

The runner, schema checker, and Rust shared model use different vocabularies for coverage outcomes. Current JSONL records mix coarse `status` values (`pass/fail/unsupported/blocked/skip-with-reason`) with ad hoc counters (`build_pass`, `mismatch`, `runtime_error`, `oracle_skipped`, `build_only`). This makes regression analysis and triage imprecise. Coverage must preserve old coarse statuses while adding precise, schema-versioned outcomes.

## Steps

1. Add `CoverageOutcome` enum: `build_pass | semantic_pass | semantic_mismatch | runtime_error | unsupported | blocked | internal_failure | verified_negative_compile | unverified_negative_compile | oracle_skipped | skip_with_reason`
2. Add `CoveragePhase` enum: `metadata | prepare | parse | compile | link | runtime | oracle | triage`
3. Add `make_record()` that emits `schema_version: 2` plus required fields and maps outcomes to legacy `status`
4. Add `--oracle-policy {auto,always,never}` flag and recompute counters from outcomes
5. Replace ad hoc runner/harness record creation with `make_record()`
6. Extend schema checker for v2 validation and v1 fallback
7. Update dashboard (`web-ui-data.py`) and differential (`differential.py`) consumers

## Acceptance

- [ ] `scripts/lib/coverage_outcome.py` exists with `CoverageOutcome`/`CoveragePhase` enums and `make_record()`
- [ ] Schema v2 lines always include `schema_version`, `status`, `outcome`, `phase`, `semantic_checked`, `build_pass`
- [ ] `mismatch`, `runtime_error`, `oracle_skipped` are no longer top-level `status` values
- [ ] Schema v1 files remain readable
- [ ] `--oracle-policy {auto,always,never}` flag implemented
