## Notes

### 2026-05-21 sampled profile

Command executed:

```bash
timeout 20m python scripts/manager.py reference-coverage test262 --semantic fast --sample 2000 --sample-seed profile-20260521 --no-dashboard-data
```

Result: exit 0.

Summary:

- Selected cases: 8,695 (`--sample 2000` is currently max files per category, not total files).
- Non-sampled cases: 44,774.
- Wall duration: 222,618 ms (3m42.6s).
- Summary counts: Pass 1, OracleSkipped 2,193, Fail 2,098, Unsupported 4,104, Blocked 14, SemSkipSample 44,774.
- Evidence artifacts: `artifacts/coverage/results/test262-profile.json`, `artifacts/coverage/results/test262-summary.json`, `reports/coverage/test262/evidence.json`.

Profile:

| Metric | Value |
|---|---:|
| `prepare_ms` | 5,082 |
| `server_wasm_emit_ms` | 214,441 |
| `iwasm_wall_ms` | 795,105 cumulative |
| `wamr_wall_ms` | 50,125 cumulative |
| `node_wall_ms` | 108,139 cumulative |
| `wasm_emit_count` | 4,423 |
| `iwasm_processes` | 4,423 |
| `node_processes` | 938 |
| `server_fallback_batches` | 72 |
| `non_sample_ms` | 188 |

Interpretation:

- Wall time is dominated by server wasm emission for the sampled executable cases.
- `--sample 2000` is misleading for a daily local run because it means "up to 2000 per category"; the actual selected set was 8,695 files.
- The CLI seed was not preserved. `scripts/run/reference-coverage.py` parses `--sample-seed`, then resets `sample_seed = os.environ.get("TS2WASM_SAMPLE_SEED")` after resolving suite paths, so output says `seed=none` and evidence records `sample_seed: null`.
- Evidence command rendering is incomplete for manager-launched sampled runs: `reports/coverage/test262/evidence.json` recorded `mise run reference-coverage -- test262 --sample 2000 --jsonl`, omitting `--semantic fast`, `--sample-seed profile-20260521`, and `--no-dashboard-data`.

## Acceptance

- [ ] A developer-facing daily test262 command exists and is documented in the issue or docs, with predictable total selected cases rather than per-category surprise. Acceptable shapes include `--sample-total N`, `--profile daily`, or a manager/mise alias that expands to an explicit sampled command.
- [ ] `--sample-seed` CLI values survive argument parsing, affect selection, and are preserved in `selection.sample_seed`, evidence JSON, and the stderr sample-mode line.
- [ ] Evidence for sampled runs records the actual semantic mode, seed, dashboard flag, selection mode, selected case count, and exact command needed to reproduce the run.
- [ ] The daily sampled semantic profile completes under 90 seconds on the current dev machine, or the implementation records a new profile proving why a different budget is required.
- [ ] `artifacts/coverage/results/test262-profile.json` separates wall-clock phase time from cumulative worker/process time so bottlenecks are readable without source-code context.
- [ ] Full test262 behavior remains unchanged when no sampled/daily profile flag is used.
