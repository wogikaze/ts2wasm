Title: Refactor backend-wasm flat runtime files into hierarchical modules
Summary: Move flat runtime_*.rs files such as runtime_async.rs toward the runtime/<domain>/ module layout already used elsewhere in backend-wasm.
Next: Define the first migration slice and convert one or more flat runtime files behind stable module re-exports.

---

## Notes

- `crates/backend-wasm/src/lib.rs` には `mod runtime_async;`, `mod runtime_promise;`, `mod runtime_typed_arrays;`, `mod runtime_dispatch_*;` のような flat module がまだ残っている一方で、同 crate では `runtime/<domain>/mod.rs` 配下へ寄せた構造も進んでいる。backend-wasm 内で module layout が二重化しており、新規追加先の判断と分割作業の単位がぶれている。
- 代表例:
  - `crates/backend-wasm/src/runtime_async.rs` (275 lines)
  - `crates/backend-wasm/src/runtime_promise.rs` (722 lines)
  - `crates/backend-wasm/src/runtime_typed_arrays.rs` (1715 lines)
  - `crates/backend-wasm/src/runtime_dispatch_array.rs` / `runtime_dispatch_date.rs` など flat dispatch modules
- `I-20260520-EA5MRA` が追っている architecture gate 全体の一部だが、この issue では backend-wasm runtime の module layout 正規化だけにスコープを絞る。サイズ gate 対応のついでに分けるのではなく、`runtime/<domain>/` の境界を先に決めて、既存 `lib.rs` からは安定した re-export / facade 経由で参照できる形へ揃える。
- 初手では一括移行しない。`async`, `promise`, `typed_arrays`, `dispatch_*` などの flat files から 1 ドメインずつ移し、各 slice で compile/test を通す。特に `runtime_typed_arrays.rs` は file-size gate の対象でもあるため、優先候補に含める。

## Acceptance

- [ ] backend-wasm runtime の flat module を `runtime/<domain>/` 配下へ移す方針が issue 内で具体化され、少なくとも 1 つの代表ファイル (`runtime_async.rs` など) が階層 module 化される
- [ ] `crates/backend-wasm/src/lib.rs` から直接ぶら下がる `runtime_*.rs` のうち、着手対象は stable facade 経由に置き換えられ、外部 API と import path の互換が維持される
- [ ] `cargo check -p ts2wasm-backend-wasm` と `mise run check architecture` が通り、移行対象に対応する allowlist / size-gate 状態が悪化しない
