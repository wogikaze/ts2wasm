## Notes

Three separate methods grouped because all crash at runtime with similar parameter handling issues.

### copyWithin (9 fail)
WAT `$array_copy_within` (mutator.rs:410) has signature:
```
(func $array_copy_within (param $arr i32) (param $target i32) (param $start i32) (param $end i32) (result i32)
```
IR pads missing args correctly (method.rs:2385-2392 and 3579-3586). WAT looks correct. May crash on edge cases:
- `end` passed as `undefined` tag — WAT checks `undefined` tag at line 444 ✅
- But `$e_raw` computation doesn't handle non-number tags for the first `if` path — entering with `end` having `undefined` tag would skip the `end` handling and fall through to `$e_raw` uninitialized? Actually looking more carefully, the `br $end_handled` at line 447 jumps to line 456 where `$count = $e_raw - $s_raw` — but `$e_raw` was set at line 446 inside the `then`, so it should be OK. But what if `$end` is passed as a number-tagged value when `$end` is supposed to be undefined? Let me trace through more carefully...

Actually, the issue with copyWithin might be more subtle — possibly related to the target/start/end clipping logic edge cases.

### fill (9 fail)
WAT `$array_fill` (mutator.rs:336) has signature:
```
(func $array_fill (param $arr i32) (param $val i32) (result i32)
```
Only accepts 2 params (array + value). But JS `fill(value, start?, end?)` can pass up to 3 args (start, end). The IR path at method.rs:2404-2409 extends all args as-is — passing N+1 args to a WAT function that only expects 2, causing stack corruption/runtime crash.

**Fix**: Add a dedicated `fill` handling clause at method.rs:2384 (like `copyWithin`) that pads missing start/end args. Or widen the WAT signature.

### includes (7 fail)
WAT `$array_includes` (accessor.rs:242) has signature:
```
(func $array_includes (param $arr i32) (param $search i32) (param $from_idx i32) (result i32)
```
Already handles missing `from_idx` padding at method.rs:2299, 3164-3174, 3341-3343. The 7 failures may be edge cases: SameValueZero comparison with -0, NaN, or sparse array handling.
