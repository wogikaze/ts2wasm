## Notes

### Root cause
Both `filter` and `every` are listed in `is_identity_array_method()` at `program_builtins.rs:494-498`:
```rust
"every" | "some" | "find" | "findIndex" | "findLast" | "findLastIndex" | "filter"
```
This causes the IR layer to drop the callback and emit a direct WAT call that checks `$truthy_bool` on each element instead of invoking the user-provided callback.

### WAT implementations (iteration.rs)
- `emit_array_filter` (line 475): takes `(param $arr i32) (result i32)` — no callback param. Uses `$truthy_bool`.
- `emit_array_every` (line 558): same pattern, takes only `$arr`, uses `$truthy_bool`.

### Fix approach
1. Remove "filter" and "every" from `is_identity_array_method()` at `program_builtins.rs:494-498`
2. The IR layer (method.rs:3163, 3332) already has a fallback path for non-identity methods that expands the callback call inline via ArrowFn/FunctionExpr expansion
3. WAT functions may become unused and can be removed or kept for other purposes

### Impact
Fixing these two methods resolves ~202 of 460 Array prototype failures (156 filter + 46 every) — the single highest-impact fix available.
