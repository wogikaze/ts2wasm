### 2026-05-16: unsupported_by_phase population fix

The full test262 corpus (53,104 cases) was already being run via `--jsonl` mode with `executed=53104`, but `unsupported_by_phase` was empty ({}) because the JSONL path's `consume_record()` only counted unsupported entries without extracting diag_code/feature/phase.

**Root cause**: The JSONL path (`consume_record()` in the `--jsonl` mode) did not aggregate `unsupported_diag_counts`, `unsupported_feature_counts`, or `unsupported_by_phase`. These were only tracked in the aggregate (non-JSONL) path. The `build_test262_jsonl_summary()` function hardcoded them to `{}`.

**Fix** in `scripts/run/reference-coverage.py`:
1. Added `unsupported_diag_counts`, `unsupported_feature_counts`, `unsupported_by_phase` counters in the JSONL path
2. Added extraction logic in `consume_record()` to parse `diag_code`, `feature` label, and `diag_phase` from the `reason` string format (`DiagCode/feature: [phase]`)
3. Threaded these counters through `build_test262_jsonl_summary()` replacing hardcoded `{}`
