## Notes

### Fix applied (2026-05-20)

**Root cause**: `AggregateError` was not in `BuiltinErrorConstructor` enum nor in `builtin_function_token_value`. When referenced as an identifier (e.g., `AggregateError.prototype`), it fell through to the `Undefined` fallback in `control.rs`.

**Fix**:
1. **`types.rs`**: Added `AggregateError` variant to `BuiltinErrorConstructor` enum with `from_name`, `name`, and `parent` (returns `Error`).
2. **`program_builtins.rs`**: Added `"AggregateError" => Some(native_error_token_value(7))` to `builtin_function_token_value`, so identifier references resolve to function tokens (offset 7 following URIError at 6).
3. **`control.rs`**: Removed `"AggregateError"` from the Undefined fallback list — now caught by `builtin_function_token_expr` before reaching it.
4. **`emitter/mod.rs`**: Added `AggregateError` arms to `builtin_error_prototype_global` and `builtin_error_stack_prefix`.
5. **`validate.rs`/`expr_emit.rs`**: Fixed `errors` field shadowing in `ErrorNew` destructuring (validation + WAT emission).
