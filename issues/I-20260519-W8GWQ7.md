## IR lowering (2026-05-22)

Lowered `yield*` delegation in the IR layer:

- **`lower_yield_star_stmt`**: New helper in `resolver/mod.rs` that lowers `yield* iterable` into a `DoWhile` loop using the iterator protocol:
  1. `iterable["@@iterator"]` → `PropertyGetDynamic`
  2. Call it → `HeapClosureCall`
  3. Loop: `iter["next"]` → `HeapClosureCall` → check `result["done"]` → yield `result["value"]`

- **Statement cases handled**:
  - `yield* iterable;` — standalone statement (Expr handler)
  - `let x = yield* iterable;` — let with target local (Let handler)
  - `x = yield* iterable;` — assign to existing local (Assign handler)
  - `let [a] = yield* iterable;` — destructure pattern (DestructureLet handler)
  - `return yield* iterable;` — delegate then return (Return handler)

- **Expression context** (e.g. `f(yield* iter)`): Still emits unsupported error with clarified message.

### Known limitation

The current generator runtime uses pre-collected yields (`GeneratorYield` + `generator_next`). The `LoweredStmt::Yield` emitted by the loop is treated as a no-op by the backend (stmt_emit.rs / mir_emit.rs evaluate and drop). This means generators with `yield*` will produce incorrect values at runtime until the backend is updated to support dynamic yields and/or execute the generator function body directly.

The IR lowering is semantically correct — the issue is entirely in the runtime/backend layer.
