## Notes

### Current state
WAT implementation `$array_at` already exists at `accessor.rs:511-548` with correct signature:
```
(func $array_at (param $arr i32) (param $idx i32) (result i32)
```
It handles negative indexing by adding `len + idx`. Internally delegates to `$array_get`.

### Root cause
`Array.prototype.at` is registered as `RuntimeFn::ArrayAt` in the manifest, spec, and catalog, but the method is not exposed as an accessible `Array` prototype property. The `at` method is listed in `is_identity_array_method` is NOT listed for `at` — it's only for methods whose WAT doesn't accept callbacks. The issue is that `at` is likely not listed in the prototype property set or the `collection_method_runtime_fn` / `collection_method_runtime_fn_arg` routing tables for the non-identity path.

### Fix approach
1. Verify that `"at"` appears in the `collection_method_runtime_fn` handler at `program_builtins.rs` (it does at line 418)
2. Check whether the method.name-based dispatch in the method call resolver correctly routes `at` to `RuntimeFn::ArrayAt`
3. The actual issue may be that `at` was never added to the prototype's enumerable method list

### Note
The WAT implementation already correctly handles ToInteger coercion for negative indices — no changes needed at the WAT level.
