## Notes

### Triage: test262 Promise failure patterns (2026-05-21)

Sampled 30 test262 built-ins/Promise tests. Results:
- 22 fail (73%), 7 unsupported (23%), 1 oracle_skipped (3%)
- Extrapolated: ~51 fail, ~16 unsupported, ~2 pass out of ~70 Promise tests

#### Failure Pattern 1: "TypeError: not a function" (15/22 = 68%)

Root cause: Promise constructor (`$promise_constructor`) accepts `$executor` parameter but never calls it. When test262 tests provide custom constructors via `Promise.all.call(fn, [])`, the executor is never invoked. This affects:
- `Promise.all` capability creation (NewPromiseCapability)
- `constructor.resolve` calls
- Custom executor setup

Affected tests: `S25.4.4.1_A2.3_T*`, `A3.1_T*`, `A4.1_T1`, `A5.1_T1`, `capability-*`, `ctx-ctor-throws`, `Symbol.species/*`

#### Failure Pattern 2: "WASM module load failed: type mismatch" (4/22 = 18%)

Root cause: `Promise.all` WAT function directly accesses array structure fields (`i32.load` on `$base`) without checking if the input is actually a valid array. When given non-array inputs, this causes stack corruption.

Affected tests: `S25.4.4.1_A2.2_T1`, `A7.1_T1`, `A7.2_T1`, `A8.1_T1`

#### Failure Pattern 3: "test262 assertion failed" (3/22 = 14%)

Root cause: Various assertion failures including:
- `Symbol.species/prop-desc.js` - `Object.getOwnPropertyDescriptor(Promise, Symbol.species)` returns something where `desc.get` is not a function (species getter never installed)
- `S25.4.4.1_A1.1_T1` - `typeof Promise.all !== "function"` (possibly assertion stub issue)
- `Symbol.species/symbol-species-name.js` - species property descriptor check

#### Missing Features (root causes)

1. **Constructor executor not called**: `$promise_constructor` stores executor param but never invokes it with resolve/reject functions. The runtime has no callable-value dispatch mechanism at WAT level.
2. **No Symbol.species getter**: `Promise[Symbol.species]` is never installed as a getter that returns `this`.
3. **No input validation in static methods**: `Promise.all`/`race`/`any`/`allSettled` assume inputs are always arrays and directly access array struct fields.
4. **No NewPromiseCapability**: Static methods create promises directly instead of going through constructor capability protocol.
5. **No microtask/async support**: Callbacks stored in slots but never invoked. No Job queue.

#### Fixes Applied (2026-06-14)

1. **Pattern 1 (executor calling) -- FIXED**: `$promise_constructor` now calls the executor
   - Added NUMBER-tagged (DirectLocalToken) and OBJECT-tagged (HeapClosure) dispatch tables
   - After allocating the promise, the executor is dispatched based on its tag
   - Executor receives `(undefined, undefined)` for resolve/reject (proper callable closures deferred)
   - File: `crates/backend-wasm/src/runtime_promise.rs`
2. Pattern 2 (Promise.all input validation) -- Already has array-tag validation in all 4 static methods; element-level wrapping with `Promise.resolve` still needed
3. Pattern 3 (Symbol.species getter) -- Not yet implemented; requires changes to how the Promise constructor exposes properties with symbol keys

#### Next Steps

1. Create proper callable resolve/reject closures for the executor (capturing the promise base)
2. Add element-level Promise.resolve wrapping in Promise.all/race/any/allSettled
3. Install Symbol.species getter on Promise constructor
4. Create node_diff fixtures for basic Promise patterns
