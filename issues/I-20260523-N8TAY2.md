## Evidence

### Binary operators (4 variants, 8 tests)
The `binary_op_instr()` catch-all in `native_lowered.rs` was replaced with specific error messages for each unhandled variant:

- `LoweredBinaryOp::Power` — "native LoweredProgram emitter does not support the ** operator as a raw wasm binary op"
- `LoweredBinaryOp::And` — "native LoweredProgram emitter does not support the && operator as a raw wasm binary op"
- `LoweredBinaryOp::Or` — "native LoweredProgram emitter does not support the || operator as a raw wasm binary op"
- `LoweredBinaryOp::NullishCoalesce` — "native LoweredProgram emitter does not support the ?? operator as a raw wasm binary op"

These four variants are already handled by upstream logic (logical short-circuit emission for And/Or/NullishCoalesce, and MathPow runtime call for Power), so the old catch-all was dead code. The new arms make the code self-documenting and produce specific diagnostics if a new code path reaches `binary_op_instr`.

### Builtin calls (console builtins, 3 tests)
The `FunctionCallKind::Builtin(builtin)` catch-all in `native_lowered.rs` was extended to:

1. **Console builtins as expressions** (`ConsoleWarn`, `ConsoleError`, `ConsoleGroup`, `ConsoleGroupEnd`, `ConsoleGroupCollapsed`, `ConsoleTime`, `ConsoleTimeLog`, `ConsoleTimeEnd`, `ConsoleCount`, `ConsoleCountReset`, `ConsoleTrace`): These are now emitted by delegating to `try_emit_console_call()` for the side effect, then pushing `ValueTag::UNDEFINED` as the expression result. Previously they fell through to a generic error.

2. **Remaining unhandled builtins**: The generic error message was replaced with a builtin-specific diagnostic that includes the `BuiltinId` debug representation.
