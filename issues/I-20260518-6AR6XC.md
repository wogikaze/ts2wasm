## Notes

### Root cause
Same `is_identity_array_method()` issue as filter/every. These methods are listed at `program_builtins.rs:494-498`:
```rust
"every" | "some" | "find" | "findIndex" | "findLast" | "findLastIndex" | "filter"
```
The IR drops the callback and WAT checks `$truthy_bool` on elements directly instead of invoking the user callback.

### WAT implementations (accessor.rs)
- `emit_array_find` (line 291): `(param $arr i32) (result i32)` — uses `$truthy_bool`
- `emit_array_find_index` (line 332): `(param $arr i32) (result i32)` — uses `$truthy_bool`
- `emit_array_find_last` (line 376): `(param $arr i32) (result i32)` — uses `$truthy_bool`
- `emit_array_find_last_index` (line 418): `(param $arr i32) (result i32)` — uses `$truthy_bool`

### Fix approach
Remove "find", "findIndex", "findLast", "findLastIndex" from `is_identity_array_method()` at `program_builtins.rs:494-498`. The IR fallback path (method.rs:3163, 3332) expands the callback call inline for non-identity methods.

### Relation to filter/every issue
Same root cause, separate issue because the methods have different WAT impl locations (accessor.rs vs iteration.rs) and different test coverage. Fixing all at once is reasonable.
