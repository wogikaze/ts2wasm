### Root Cause
`builtin_ctor_base = function_ids.len()` did not account for function IDs consumed by `collect_preindexed_function_properties`. When the Python test262 harness (INLINE_STA_JS, INLINE_ASSERT_JS) prepended function property assignments like `Test262Error.thrower = function() {}` and `assert.sameValue = function() {}`, these consumed FuncIds starting from `function_ids.len()`. Builtin constructors (RegExp, Object, Error, etc.) also started from `function_ids.len()`, creating FuncId conflicts. Pre-indexed property functions went to `generated_functions` (appended after `functions_by_id`), while builtins went to `functions_by_id` at the same indices, producing the "function id X does not match its index Y" mismatch.

### Fix
1. **crates/ir/src/lowered/program.rs**: Moved `builtin_class_parents`, `needed_builtins`, `builtin_ctor_base`, `builtin_ctor_ids` computation EARLIER (before `collect_preindexed_function_properties`). Offset `next_func_id` by `needed_builtins.len()` so pre-indexed function properties start AFTER builtins. Created `functions_by_id` with `function_ids.len() + needed_builtins.len()` slots to accommodate builtin stubs.

2. **crates/ir/src/lowered/validate.rs**: Changed ObjectDefineProperty, ObjectGetOwnPropertyDescriptor, ObjectGetPrototypeOf, ObjectSetPrototypeOf argument-count checks from `InvariantViolation` to `UnsupportedSyntax`.

3. **crates/ir/src/lowered/mir_validate.rs**: Same changes as validate.rs plus added `unsupported()` helper function.
