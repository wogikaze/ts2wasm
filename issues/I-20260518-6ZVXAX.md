## Notes

### Fix: Set/Map prototype property routing (2026-05-20)

**Root cause:** 137 test262 built-ins/Set+Map tests failed because `Set.prototype.has`, `Set.prototype.delete`, `Set.prototype.forEach`, `Map.prototype.get`, `Map.prototype.set`, `Map.prototype.has`, `Map.prototype.delete`, `Map.prototype.forEach` property access returned `undefined` — the IR had no routing for these prototype property accesses.

**Layer 1: RuntimeFn variants and WAT implementations (commit `f0c32872e`)**
- Added 16 new `RuntimeFn` variants: SetPrototypeHasGet/Set, SetPrototypeDeleteGet/Set, SetPrototypeForEachGet/Set, MapPrototypeGetGet/Set, MapPrototypeSetGet/Set, MapPrototypeHasGet/Set, MapPrototypeDeleteGet/Set, MapPrototypeForEachGet/Set
- Added 8 new `RuntimeGlobal` variants for each prototype method
- Added WAT getter/setter emit functions in `runtime/collections/emit.rs`
- Added dispatch arms in `runtime_dispatch_collections.rs`
- Added RuntimeSpec entries, manifest entries

**Layer 2: IR-level routing (commit `dc55c2bcd`)**
- Added `matches_map_prototype_object()` and `is_map_prototype_property()` in `mod.rs`
- Added property access handlers in `property.rs` for Set.prototype.has/delete/forEach and all Map.prototype methods
- Added assignment handlers in `assignment.rs` for all Set/Map prototype property sets
