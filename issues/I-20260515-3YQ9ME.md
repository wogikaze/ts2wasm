## Problem

The coverage gate (`scripts/gate/coverage.py`) already does matrix delta and shard baseline regression, but it is not schema-version aware, cannot reject unknown-unsupported counts above a threshold, and cannot require evidence keys. Making it outcome-aware and evidence-aware is required before the gate can enforce v2 schema quality.

## Steps

1. Add gate flags `--schema-version N`, `--max-unknown-unsupported N`, `--require-evidence-key KEY`
2. Count shards by `outcome` with legacy `status` fallback
3. Reject semantic/build counter contradictions
4. Update matrix metadata comments/footnotes for schema version and oracle policy

## Acceptance

- [ ] `--schema-version`, `--max-unknown-unsupported N`, `--require-evidence-key KEY` flags added
- [ ] Shards counted by `outcome` with legacy fallback
- [ ] Semantic/build counter contradictions rejected
- [ ] Matrix metadata updated for schema version and oracle policy

```bash
python scripts/gate/coverage.py --shards --jsonl-file artifacts/coverage/results/test262-results.jsonl --schema-version 2 --max-unknown-unsupported 999999
python scripts/gate/coverage.py --check-regression --jsonl-file artifacts/coverage/results/test262-results.jsonl --schema-version 2
mise run update-coverage-matrix -- --check
```

## Non-goals

- Do not replace the existing gate delta mode
- Do not require full-corpus execution for PR gates

## Risk

Existing shard baseline may shift with outcome-based counting; baseline may need regeneration.
