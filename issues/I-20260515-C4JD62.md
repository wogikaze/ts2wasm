## Problem

Coverage failures must be issue-ready. Current counters exist, but no stable top-N JSON/Markdown report or single feature-label owner map exists. The test262 harness has its own feature labels, creating a duplicate source of truth.

## Steps

1. Create `scripts/lib/coverage_labels.py` with label map (`parser-syntax`, `typescript-erase`, `unsupported-builtin`, `object-kernel`, `array-exotic`, `gc-runtime`, `node-host`, `test262-harness`, `unknown-unsupported`) and owner map (`parser | frontend | ir | runtime | host | harness | reference`)
2. Remove duplicate feature-label logic from `test262_harness.py`
3. Add `--triage-report-dir DIR` and `--top-failures N` flags to `reference-coverage.py`
4. Emit `<suite>-triage.json` and `<suite>-triage.md` sorted by count then stable keys
5. Make `reference-triage.py --help` lazy (no `ts2wasm` binary required at import)

## Acceptance

- [ ] `scripts/lib/coverage_labels.py` exists with label and owner maps
- [ ] Duplicate feature-label logic removed from `test262_harness.py`
- [ ] `--triage-report-dir DIR` and `--top-failures N` flags in `reference-coverage.py`
- [ ] Triage JSON (`<suite>-triage.json`) and Markdown (`<suite>-triage.md`) emitted
- [ ] `reference-triage.py --help` is lazy (no binary required at import)
- [ ] Top-N buckets sorted deterministically
- [ ] Labels match `docs/26-semantic-feature-matrix.md`

```bash
python scripts/run/reference-triage.py --help
mise run reference-coverage -- test262 --jsonl --sample 1 --jobs 1 --no-semantic --no-dashboard-data --triage-report-dir artifacts/coverage/triage --top-failures 10
test -f artifacts/coverage/triage/test262-triage.json
test -f artifacts/coverage/triage/test262-triage.md
```

## Non-goals

- Do not auto-create issue files from triage output
- Do not require eliminating all unknown unsupported cases

## Risk

Label renames can break history; keep `legacy_label` for one migration wave when available.
