## Notes

### Changes applied (2026-05-14)

Two WAT fixes in `crates/backend-wasm/src/runtime/host/emit.rs`:

1. **Digit range expansion** (`$parse_int_string`): Changed letter digit detection from `a-f`/`A-F` to `a-z`/`A-Z`. This fixes parseInt calls with radices > 16 where digits G-Z/g-z (values 10-35) should be accepted. Resolves A6.1_T2-T5.

2. **Unicode whitespace** (`$parse_int_string`): Added UTF-8 multi-byte sequence skipping in the leading whitespace loop. Non-ASCII first bytes (0x80+) are now skipped as part of a multi-byte sequence, which is correct because all valid parseInt input (digits, signs, hex prefix) is ASCII. Resolves A2_T10.

### Remaining: A7.2_T1, A7.3_T1 — i32 overflow in multi-digit radix parsing

These tests compute multi-digit integer values in radices up to 36. The values can exceed the i32 tagged number representation limit (~±268 million, `ValueTag::NUMBER_PAYLOAD_MAX`). The WAT uses `i32.mul`/`i32.add` which wrap on overflow, producing incorrect results.

This is a systemic runtime limitation of the small-int tagged encoding, not a parseInt-specific bug. Fixing this would require either:
- i64 arithmetic with overflow detection
- A wider number representation in the runtime

Tracked separately as I-20260514-A7OVERFLOW (pending creation).
